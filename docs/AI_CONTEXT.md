# 🤖 AI / Contributor Context

This file is a compact orientation surface for any AI system, reviewer, or contributor entering the repository without prior conversation context.

## 🪁 What this repository is

Mentaury-Kernel is a **technology-neutral composition specification** governing semantic boundaries between independently owned domains, currently centered on:

```text
🧬 Velantrim Native Kernel
        ↕ bounded semantic composition
🌀 Mentaury Soul
```

Mentaury-Kernel owns only the composition boundary.

## 🚫 What you must not infer

Repository existence does **not** imply:

```text
runtime exists
Port implementation exists
cognition exists here
identity authority exists here
truth authority exists here
action authority exists here
production is authorized
GitHub automatically became semantic Canon
```

Do not create these by implication.

## 🧭 Ownership routing

Before proposing a feature or invariant:

```text
internal cognition / inquiry / identity semantics
→ 🌀 Mentaury Soul

internal epistemic-history / revision / retention / loss semantics
→ 🧬 Velantrim Native Kernel

cross-domain preservation / authority / scope / declared loss
→ 🪁 Mentaury-Kernel

authorization procedure
→ 🏛️ owning Governance domain

LLM / DB / graph / vector / language / framework choice
→ implementation profile, not semantic Canon
```

## 🧪 Evidence discipline

Current architecture conformance scenarios are documentation-level expectations only.

```text
DOCUMENT_INTERNAL_CONSISTENCY_ONLY
```

Never translate a documented `PASS` into executable evidence, independent review, implementation evidence, or runtime authorization unless such evidence is separately present and explicitly bound.

## 🔬 Inclusion test

For every proposed new law, ask:

1. What concrete cross-domain failure becomes possible without it?
2. Is that failure already covered?
3. Who owns the internal semantics?
4. Can the rule stay technology-neutral?
5. Would adding it create duplicate authority?

If the proposal is merely interesting or architecturally compatible, keep it out of Canon.

```text
ARCHITECTURAL FIT ≠ ARCHITECTURAL NECESSITY
```

## 🛑 Stop conditions

Stop and request an explicit bounded decision before introducing any of the following:

- runtime code;
- executable autonomous loops;
- a specific wire protocol as Canon;
- a storage/database dependency as Canon;
- an LLM/model dependency as Canon;
- identity or truth adjudication;
- action authority;
- production/deployment authorization;
- a new owner over existing Native or Soul semantic domains;
- a permanent Notion↔GitHub semantic-authority model not explicitly decided by the Owner.

When uncertain, preserve the boundary and record the uncertainty rather than silently resolving it through implementation.
